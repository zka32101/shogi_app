# build-and-test スキル

改修セッション時にビルド完了後、自動的にエミュレータテストを実行するスキル。

## 用途

```bash
/build-and-test <app_name>
```

例：
```bash
/build-and-test prefecture_defense
```

## テスト観点

1. **起動テスト** ✅
   - アプリが正常に起動できるか
   - クラッシュなく初期画面が表示されるか

2. **各連携テスト** ✅
   - バックエンド API への接続
   - SNS プラットフォーム（TikTok Live など）との連携
   - Firebase / Analytics との連携

3. **購入画面テスト** ✅
   - Google Play Billing の UI が正常に表示されるか
   - 購入フローの初期段階が動作するか

4. **認証テスト** ✅
   - ログイン画面が表示されるか
   - 認証フローが開始できるか
   - トークン取得エラーがないか

5. **広告テスト** ✅
   - Google Mobile Ads SDK が初期化されるか
   - 広告フォーマット（バナー、インタースティシャル、リワード）が読み込めるか
   - 広告関連のエラーログがないか

## 実行内容

```
1. 📦 ビルドファイル確認
   └─ apk ファイルの存在確認

2. 📱 デバイス接続確認
   └─ adb devices で接続確認

3. 📥 アプリインストール
   └─ adb install -r で既存版を上書きインストール

4. 🚀 起動テスト
   ├─ アプリを起動
   ├─ 10秒待機（初期化処理完了待ち）
   └─ クラッシュ判定

5. 🔗 連携テスト
   ├─ API 連携ログ確認
   ├─ 外部ライブラリ初期化確認
   └─ ネットワークエラーログ確認

6. 💰 購入画面テスト
   ├─ Google Play Billing SDK 初期化確認
   ├─ 購入関連エラーログ確認
   └─ UI テクスチャロード確認

7. 🔐 認証テスト
   ├─ ログイン UI 描画確認
   ├─ 認証フロー開始確認
   └─ トークンエラーログ確認

8. 📣 広告テスト
   ├─ Google Mobile Ads SDK 初期化確認
   ├─ 広告フォーマット読み込み確認
   └─ 広告関連エラーログ確認

9. 📋 最終レポート生成
   └─ 各テスト観点の合否判定
```

## テスト結果の見方

### ✅ 合格
- すべてのテスト観点が確認された
- エラーログが最小限（警告は許容）

### ⚠️ 要確認
- 一部の連携でエラーが検出された
- ネットワーク接続を確認してから再テスト

### ❌ 失敗
- アプリのクラッシュ
- 基本的な起動失敗
- 複数の連携エラー

## 前提条件

- ビルドが完了している（apk ファイルが存在）
- Android SDK がインストール済み
- エミュレータまたは物理デバイスが接続可能
- adb コマンドが利用可能

## トラブルシューティング

### adb: command not found
```bash
export PATH="$PATH:$ANDROID_SDK_ROOT/platform-tools"
```

### デバイスが見つからない
```bash
# エミュレータを起動
emulator -avd <AVD_NAME> -no-snapshot-load &
# または物理デバイスを USB 接続
```

### インストール失敗
```bash
# 既存アプリをアンインストール
adb uninstall com.example.<app_name>
```

## 改修セッションでの自動実行

改修セッション開始時に以下を実行：
```bash
/build-and-test <app_name>
```

または明示的に実行して詳細ログを確認。
